# EPI-ClimaNuvem — Playwright + C# Test Suite

Playwright (.NET) + NUnit 4 test suite for [EPI-ClimaNuvem](https://gitlab.com/HP-SCDS/Observatorio/2025-2026/climanuvem/epi-climanuvem),
covering the same scenarios as the [`selenium-java`](../selenium-java) and [`cypress-js`](../cypress-js) suites in this
repository, written in idiomatic Playwright/.NET rather than ported line-for-line.

Two test layers:

- **API tests** (`Tests/Api/`) — REST contract tests against the FastAPI backend through Playwright's
  `IAPIRequestContext` (no browser needed).
- **System tests** (`Tests/E2e/`) — Playwright-driven tests against the Expo web frontend (English UI), using a Page
  Object Model and `data-testid` locators (`Page.GetByTestId`, ids listed in `Common/TestIds.cs`).

## Quick start

### 1 — Deploy the SUT

The stack is three layered Compose files: the production `sut/backend/docker-compose.yml`, the dev override (adds the
Firebase Auth emulator) and `docker-compose.test.override.yml` (test mode, ports, images). The shared helper
`selenium-java/scripts/sut-compose.sh` stacks them; run it from the repository root:

```bash
bash selenium-java/scripts/sut-compose.sh up --build -d db firebase-emulator backend frontend
ACCOUNTS_FILE="$PWD/playwright-csharp/Resources/accounts.local.csv" bash selenium-java/scripts/seed-firebase-emulator.sh
```

`seed-firebase-emulator.sh` creates the login/profile accounts in the Firebase emulator and writes the accounts CSV
used by the system tests (see [Configuration](#configuration)). To reuse prebuilt images (as CI does), set
`BACKEND_IMAGE` / `FRONTEND_IMAGE` / `FIREBASE_EMULATOR_IMAGE` and add `--no-build`. If port 8000 is taken, set
`BACKEND_PORT` and run the tests with `SUT_URL=http://localhost:<port>`.

| Service | URL |
|---|---|
| Backend (FastAPI) | http://localhost:8000 |
| Frontend (Expo web) | http://localhost:5173 |
| Firebase Auth emulator | http://localhost:9099 |

### 2 — Build and install the Playwright browsers

```bash
cd playwright-csharp
dotnet build
pwsh bin/Debug/net10.0/playwright.ps1 install --with-deps chromium    # drop --with-deps outside Linux CI
```

`playwright.ps1` is generated by the `Microsoft.Playwright` build target, so it only exists after the first
`dotnet build`. API tests do not need a browser; only `Tests/E2e` does.

### 3 — Run the tests

```bash
dotnet test                                                           # everything (API + system)
dotnet test --filter "FullyQualifiedName~Tests.Api"                    # API tests only
dotnet test --filter "FullyQualifiedName~Tests.E2e"                    # system tests only (drives Chromium)

dotnet test --filter "FullyQualifiedName~LoginSystemTests"
dotnet test --filter "FullyQualifiedName~RegisterSystemTests"
dotnet test --filter "FullyQualifiedName~ProfileSystemTests"

CI=true dotnet test --filter "FullyQualifiedName~Tests.E2e"            # headless Chromium (CI or no display)
```

### Real image-analysis tests with Ollama

The default deployment starts the backend with `DISABLE_WORKER=true`, so `dotnet test` skips the real image-analysis
suite and does not require Ollama. To exercise the full flow, start the optional Ollama services as well:

```bash
WITH_OLLAMA=true bash selenium-java/scripts/sut-compose.sh up --build -d db firebase-emulator ollama ollama-pull backend frontend
REAL_OLLAMA_TESTS=true dotnet test --filter "FullyQualifiedName~ImageAnalysisSystemTests"
```

The override enables the analysis worker and starts an Ollama container; the model `${OLLAMA_MODEL:-gemma4:e4b}` must
be pulled into it (`docker exec climanuvem_test_ollama ollama pull <model>`). The first run can take longer while the
model downloads. Without `REAL_OLLAMA_TESTS=true`, every test in `ImageAnalysisSystemTests` reports as **skipped**
(`Assert.Ignore`), not run.

### 4 — Tear down

```bash
bash selenium-java/scripts/sut-compose.sh down --volumes
```

## API under test

Every endpoint lives under `/api/v1` (the unversioned `/ping`, `/`, `/test` and the public `/uploads` mount return `404`).
Analysis endpoints, the image endpoint and `GET /api/v1/test` (test mode only) require `Authorization: Bearer <token>`
(a missing header returns `401 NOT_AUTHENTICATED`). The suite is the same contract implemented by `selenium-java` and
`cypress-js`.

| Method and path | Success | Errors asserted by the suite |
|---|---|---|
| `POST /api/v1/analyses` (multipart: `file`, `location`, `latitude`, `longitude`, `fcmToken`, `includeExplainability`) | `202`, `Location: /api/v1/analyses/{id}`, body `{"id", "status": "analyzing"}` | `422 IMAGE_EMPTY`, `413 IMAGE_TOO_LARGE_MAX_5MB`, `415 INVALID_IMAGE_FORMAT_JPG_ONLY`, `422` missing file |
| `GET /api/v1/analyses?page=&size=` | `200` array (newest first), `X-Total-Count` header | `422` for `page<0`, `size` outside 1..100 |
| `GET /api/v1/ping`, `GET /api/v1/` (also `/api/v1`) | `200` `{"ping":"pong"}` / `{"service":"ClimaNuvem API","status":"ok"}`, no auth | legacy `GET /ping` -> `404` |
| `GET /api/v1/test` (test mode) | `200` `{"message","user"}` | `401` without token |
| `GET /api/v1/analyses/{id}` | `200` analysis object; `imageUrl` = `/api/v1/analyses/{id}/image` | `404 ANALYSIS_NOT_FOUND` |
| `PATCH /api/v1/analyses/{id}` body `{"status": "cancelled"}` | `200` updated object | `404`, `409 ANALYSIS_NOT_CANCELLABLE`, `422` other status |
| `GET /api/v1/analyses/{id}/image` | `200` `image/jpeg` (bytes start `FF D8 FF`), owner only | `401 NOT_AUTHENTICATED`, `404 ANALYSIS_NOT_FOUND`; `GET /uploads/x.jpg` -> `404` |
| `DELETE /api/v1/analyses/{id}` | `204`, empty body | `404 ANALYSIS_NOT_FOUND` |
| `DELETE /api/v1/analyses` | `204`, empty body | - |

Unsupported methods return `405` with an `Allow` header listing every method of the path (`GET, POST, DELETE` on the
collection; `GET, PATCH, DELETE` on `/{id}`). Errors are `application/problem+json` with `status` and a machine-code
`detail`.

## Configuration

System-test accounts are loaded from a CSV file. With the Firebase emulator, `seed-firebase-emulator.sh` creates the
accounts and writes the CSV for you (see Quick start). To create it by hand, start from the template:

```bash
cp Resources/accounts.template.csv Resources/accounts.local.csv
```

`accounts.local.csv` is ignored by Git:

```csv
role,email,password,verified,description
login_user,user@example.com,secret,true,Existing account for login tests
profile_user,verified-user@example.com,secret,true,Verified account for profile tests
unknown_user,missing@example.test,wrong-password,false,Non-existing account for negative login tests
```

Roles:

- `login_user`: existing account used by `LoginSystemTests` and by the "email already in use" registration case.
- `profile_user`: verified account used by authenticated profile tests. May be the same account as `login_user`.
- `unknown_user`: account expected not to exist, used for negative login attempts.

`LoginSystemTests` and `ProfileSystemTests` use `[TestCaseSource]` to run once per `login_user` / `profile_user` row,
each in its own fresh browser context (courtesy of the Playwright `PageTest` base class).

All settings are plain environment variables, read by `Common/TestSettings.cs`:

| Variable | Default | Description |
|---|---|---|
| `SUT_URL` | `http://localhost:8000` | Backend base URL used by API tests |
| `FRONTEND_URL` | `http://localhost:5173` | Frontend base URL used by system tests |
| `TEST_TOKEN` | `test-token-climanuvem` | Bearer token sent by API tests |
| `HTTP_TIMEOUT_MS` | `10000` | Per-request timeout for API tests |
| `ANALYSIS_TIMEOUT_MS` | `360000` | Maximum wait for real image-analysis completion |
| `ACCOUNTS_FILE` | `Resources/accounts.local.csv` | CSV file with system-test accounts |
| `REGISTER_EMAIL_DOMAIN` | `gmail.com` | Domain used for unique registration-test emails |
| `FIREBASE_WEB_API_KEY` | _(unset)_ | Optional Firebase Web API key used to delete the account created by `RegisterSystemTests` |
| `REAL_OLLAMA_TESTS` | `false` | Set `true` to enable `ImageAnalysisSystemTests` |
| `PASSWORD_POLICY_ENFORCED` | `false` | Set `true` against a real Firebase project that enforces the uppercase + number password policy; otherwise `PasswordPolicyViolationsAreRejected` is skipped (the Auth emulator cannot enforce it) |
| `CI` | _(unset)_ | Set to `true` for headless Chromium |

## Test architecture

```
Common/
├── TestSettings.cs      Environment-driven settings
├── ApiTestBase.cs       API base: URL builders, one request helper (IAPIRequestContext), one multipart upload
│                        helper, problem+json / 405 assertions, a single polling helper
├── ApiResponse.cs       Fully-read response (status, headers, body) so Playwright responses are disposed immediately
├── TestImages.cs        JPEG fixtures loaded from Resources/images + derived invalid payloads
├── TestIds.cs           data-testid constants shared with the frontend
├── BrowserTestBase.cs   Playwright PageTest base + navigation entry points
├── TestAccount.cs       Account row used by [TestCaseSource]-driven system tests
└── TestAccounts.cs      CSV loader and role lookup

Pages/                   Page Object Model — one class per screen, testid-based locators
Tests/
├── Api/                 PingTests, AuthTests, AnalysisTests, CancelTests, DeleteTests, HistoryTests, ImageTests,
│                        ImageAnalysisSystemTests (opt-in, real Ollama)
└── E2e/                 LoginSystemTests, RegisterSystemTests, ProfileSystemTests

Resources/
├── accounts.template.csv   Versioned example for system-test account data
├── accounts.local.csv      Local/CI account data, ignored by Git
└── images/                 tiny.jpg, cloudy.jpg, clear-sky.jpg (checked-in JPEG fixtures)
```

Design notes:

- **Single request path.** Every API call goes through `ApiTestBase.SendAsync`; multipart uploads go through
  `UploadAsync` (camelCase fields, `file` omitted when `null`); error responses are asserted with `AssertProblem`.
  Responses are read into `ApiResponse` and disposed straight away, and the request context is disposed per fixture.
- **No hard sleeps.** Waiting for an analysis uses `PollUntilAsync` (probe + predicate + timeout); the UI side relies
  on Playwright auto-waiting.
- **NUnit 4 constraint model only.** Grouped checks use `using (Assert.EnterMultipleScope()) { ... }` (the
  `Assert.Multiple(...)` overloads are ambiguous with lambdas in NUnit 4.6).
- **No image library.** JPEG fixtures are plain files under `Resources/images` (copied to the output folder by the
  csproj), so there is no dependency on SixLabors.ImageSharp, whose 3.1.x line has known vulnerabilities and whose newer
  lines require a commercial license.
- **Package hygiene.** `TreatWarningsAsErrors` is on; `dotnet list package --vulnerable --deprecated
  --include-transitive` reports nothing.

### UI test conventions

- Page objects and tests locate elements **only by `data-testid`**, through the constants in `Common/TestIds.cs`
  (mirrors the `testID` props in `sut/frontend`; React Native Web renders them as `data-testid`). When a screen changes,
  add or rename the id in both places.
- The UI under test must run in **English** (`EXPO_PUBLIC_DEFAULT_LANGUAGE=en`, already set by the test compose override).
- Hidden-but-mounted previous screens are handled once, in `BasePage.ByTestId` (visible elements only).
- The timeout is configured once, in `BrowserTestBase`. Assertions are Playwright web-first `Expect(...)`; NUnit
  `Assert.That` is used only for non-Playwright values.
- The Firebase Auth emulator answers wrong-password / unknown-email more specifically than real Firebase, so the login
  assertions accept both wordings.

## Test mode

The backend is started with `TEST_MODE=true` and `DISABLE_WORKER=true` (see the test override in `selenium-java/scripts`):

- **Any Bearer token is accepted** — API tests send a fixed token (so there is no "invalid token" test); system tests
  log in against the Firebase Auth emulator.
- **Firebase is not initialised against production** — no service account key is needed.
- **Ollama worker is disabled** — analyses stay in `analyzing`, which makes cancel tests deterministic.

## CI notes

- The `e2e-playwright-csharp` job in `.github/workflows/ci-cd.yml` mirrors the
  Cypress job: load the prebuilt images, start the SUT with `sut-compose.sh up --detach --no-build db firebase-emulator
  backend frontend`, wait for `/api/v1/ping`, `:5173` and `:9099`, seed the emulator with `ACCOUNTS_FILE` pointing at
  `playwright-csharp/Resources/accounts.local.csv`, then `actions/setup-dotnet` (from `global.json`), `dotnet build`,
  `pwsh bin/Release/net10.0/playwright.ps1 install --with-deps chromium` and `dotnet test --logger trx`.
- Set `CI=true` for headless Chromium; cache `~/.nuget/packages` and `~/.cache/ms-playwright` between runs.
- Upload `TestResults/` and, on failure, the SUT container logs (`sut-compose.sh logs`).
